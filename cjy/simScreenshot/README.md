# 시뮬레이션 결과 — 탐지 → 티켓 → 알림

> BastionPay 보안 이벤트를 트리거로 재현했을 때, **Graylog 탐지(search/alert) → 보안 대시보드 티켓 생성 → Discord 알림 → (CRITICAL은) Telegram 알림**까지 이어지는 전체 흐름을 캡처한 결과입니다.
> 재현 방법은 [../attack_trigger/README.md](../attack_trigger/README.md), 탐지·대응 설정은 [../HowToSetUp/](../HowToSetUp/)를 참고하세요.
> 시연 일시: 2026-11-11 (출발지 IP는 대부분 `192.168.3.12`, P4b만 모의 로그 `192.168.3.207`)

---

## 1. 이벤트별 처리 결과 요약

| 이벤트 | 등급 | Graylog Alert | 티켓 | Discord | Telegram |
|---|---|---|---|---|---|
| P1 반복 로그인 실패 | LOW | O | O (#95, #100) | O | — |
| P2 동일 IP 다중 계정 로그인 실패 | MEDIUM | O | O (#96) | O | — |
| P3 동일 출발지 반복 이체 실패·환불 | MEDIUM | O | O (#97) | O | — |
| P4a ADMIN 권한 탈취 시도 | HIGH | O | O (#98) | O | — |
| P4b 비정상 ADMIN 권한 승급 침해 | **CRITICAL** | O | O (#99) | O | **O** |
| P5 동일 계정 이체 요청 급증 | LOW | O | O (#101) | O | — |
| P6 서버 API 인증 실패 | — | O | 미생성 | O (운영자 알림) | — |

- 모든 이벤트가 Graylog에서 탐지(Alert)되고, 공격 경보는 보안 대시보드에 **인시던트 티켓**으로 생성됩니다.
- 생성된 티켓은 **Discord**로 알림이 가고, **CRITICAL 등급(P4b)** 만 추가로 **Telegram**까지 발송됩니다.
- P6(서버 API 인증 실패)은 설계대로 **티켓을 만들지 않고 Discord 운영자 알림만** 보냅니다.

## 6. 중복 탐지에 대한 참고

Graylog 쪽에서는 **같은 공격에 대해 Alert이 여러 번 중복으로 잡혔습니다.** (검색 시간 범위가 실행 주기보다 길어, 같은 로그가 범위 안에 남아 있는 동안 매 실행마다 다시 집계되기 때문입니다. 2장 Alert 캡처에서 같은 이벤트가 여러 줄 보이는 것이 이 때문입니다.)

다만 **중복 로그인 실패(P1)를 제외하면, Discord 알림이나 인시던트 티켓이 중복으로 생성되지는 않았습니다.**
- 대시보드 티켓 목록(3장)에서 P1(반복 로그인 실패)만 티켓이 2개(#95, #100) 생겼고, 나머지 이벤트(P2·P3·P4a·P4b·P5)는 각각 1개씩만 생성되었습니다.
- Discord 알림(4장)도 같은 양상으로, P1 외에는 이벤트별 1건씩만 전송되었습니다.
- 같은 출발지 IP의 열린 티켓은 하나로 유지·갱신되고, Graylog 쪽 알림은 grace period로 억제되기 때문입니다.

> Graylog Alert 중복은 이벤트 정의의 검색 범위·실행 주기·grace period 설정을 조정해 최소화했으며, 이후로도 계속 다듬을 예정입니다. (설정 기준: [../HowToSetUp/graylog-setup.md](../HowToSetUp/graylog-setup.md))

### 향후 과제 — 중복 탐지 방지
현재는 설정 조정으로 중복을 "줄인" 상태이고, 티켓·Discord 중복은 앱의 티켓 갱신과 grace period로 막고 있습니다. 다만 Graylog Alert 자체의 중복은 완전히 없애지 못했고, 반복 로그인 실패(P1)는 티켓이 중복으로 생기는 경우가 남아 있습니다. 앞으로 아래를 개선 과제로 둡니다.

- 검색 범위·실행 주기·grace period를 이벤트별 특성에 맞게 더 정밀하게 맞춰 Alert 중복 최소화
- 반복 로그인 실패(P1)의 티켓 중복 생성 원인 분석 및 제거
- 같은 사건이 여러 이벤트 정의에 동시에 걸릴 때의 중복 정리(상관/그룹핑) 방안 검토
